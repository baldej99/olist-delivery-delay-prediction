# Прогнозирование задержек доставки Olist

Проект по раннему прогнозированию задержек доставки заказов на данных бразильского маркетплейса Olist.

## Постановка задачи

Цель проекта — определить в момент оформления заказа, существует ли повышенный риск его доставки позже обещанной даты.

Целевая переменная `is_delayed` принимает значение `1`, если фактическая дата доставки покупателю оказалась позже расчётной даты, и `0` в остальных случаях.

Чтобы избежать утечки данных, при прогнозировании используются только признаки, доступные на момент оформления заказа. Фактические даты передачи перевозчику и доставки покупателю в модель не включаются.

## Данные

Используется открытый датасет [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce).

В проект вошли таблицы с информацией о:

* заказах;
* покупателях;
* товарах;
* продавцах;
* позициях заказа;
* географическом расположении покупателей и продавцов;
* переводах категорий товаров.

После отбора доставленных заказов и обработки пропусков итоговый датасет содержит `96 470` заказов. Общая доля задержек составляет около `6,8%`.

Исходные и обработанные данные не хранятся в репозитории.

## Этапы проекта

1. Изучение структуры и качества исходных таблиц.
2. Очистка данных и объединение таблиц на уровне заказа.
3. Создание признаков, доступных на момент оформления заказа.
4. Исследовательский анализ данных.
5. Разделение данных по времени на обучающую и контрольную выборки.
6. Сравнение исходного и расширенного наборов признаков.
7. Проверка логистической регрессии и `HistGradientBoostingClassifier`.
8. Подбор параметров и оценка итоговой модели.
9. Интерпретация результатов с помощью permutation importance.

## Признаки

Исходный набор включает:

* обещанный срок доставки;
* месяц, день недели и час оформления заказа;
* штат покупателя;
* количество позиций, товаров, продавцов и категорий;
* суммарную стоимость товаров и доставки;
* суммарный вес и объём заказа.

Дополнительно были рассчитаны:

* максимальное расстояние доставки;
* основной штат продавца;
* основная категория товара;
* признак совпадения штатов покупателя и продавца.

## Методика оценки

Поскольку данные имеют временную структуру, случайное перемешивание не используется.

Последние `20%` заказов выделены в контрольную выборку, а выбор признаков, алгоритма и параметров проводится на обучающей части с помощью `TimeSeriesSplit`.

Основной метрикой выбран `PR-AUC`, поскольку задержанные заказы составляют меньшинство. Дополнительно рассчитывается `ROC-AUC`.

## Результаты

| Модель                                          | Средний PR-AUC на CV | PR-AUC на контрольной выборке | ROC-AUC на контрольной выборке |
| ----------------------------------------------- | -------------------: | ----------------------------: | -----------------------------: |
| Исходная логистическая регрессия                |                0,150 |                        0,0757 |                         0,6988 |
| Расширенная логистическая регрессия             |                0,163 |                             — |                              — |
| Настроенная расширенная логистическая регрессия |                0,166 |                        0,0748 |                         0,7020 |
| HistGradientBoosting на расширенном наборе      |                0,140 |                             — |                              — |

Дополнительные признаки улучшили результат логистической регрессии на временной кросс-валидации, но преимущество не подтвердилось на более поздней контрольной выборке. Поэтому итоговой моделью выбрана исходная логистическая регрессия.

На контрольной выборке доля задержек составляет `3,5%`, поэтому случайный базовый уровень PR-AUC равен `0,0349`. PR-AUC итоговой модели превышает его примерно в `2,17` раза.

Permutation importance показал, что главным источником прогностического сигнала остаётся обещанный срок доставки. Среди новых признаков наибольшую пользу дали основной штат продавца и расстояние доставки. Основная категория товара почти не повлияла на результат, а признак совпадения штатов оказался нестабильным на более позднем периоде.

Ограниченное качество модели может быть связано с отсутствием оперативной информации о загрузке продавцов и логистических центров, перевозчике, погодных условиях и ситуации на маршруте. Такие данные отсутствуют в исходном датасете или недоступны в момент оформления заказа.

## Структура проекта

```text
olist-delivery-delay-prediction/
├── data/
│   ├── raw/                    # исходные CSV-файлы
│   └── processed/              # подготовленный dataset.csv
├── notebooks/
│   ├── data_understanding.ipynb
│   ├── data_preparation.ipynb
│   ├── exploratory_data_analysis.ipynb
│   └── modeling.ipynb
├── .gitignore
├── README.md
└── requirements.txt
```

Каталог `data` используется локально и исключён из репозитория.

## Запуск проекта

1. Склонировать репозиторий.
2. Установить зависимости:

```bash
pip install -r requirements.txt
```

3. Скачать датасет Olist и поместить CSV-файлы в `data/raw/`.
4. Последовательно выполнить ноутбуки:

```text
data_understanding.ipynb
data_preparation.ipynb
exploratory_data_analysis.ipynb
modeling.ipynb
```

Ноутбук `data_preparation.ipynb` создаёт файл `data/processed/dataset.csv`, который используется на следующих этапах.
